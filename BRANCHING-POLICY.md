# Infrastructure Branching Policy

## 1. Main Branch
- Contains stable and approved infrastructure code.
- Direct commits are discouraged.
- Changes must go through Pull Requests.

## 2. Feature Branches
- All new changes must use feature branches.
- Naming format: feature/description
- Example: feature/network-security-update

## 3. Commit Policy
- Use meaningful commit messages.
- Keep changes focused and documented.

## 4. Pull Request Policy
- Every feature branch must create a Pull Request.
- Changes must be reviewed before merging.
- Merge only after approval and successful checks.

## 5. Merge Strategy
- Merge approved changes into main.
- Delete merged feature branches when appropriate.
